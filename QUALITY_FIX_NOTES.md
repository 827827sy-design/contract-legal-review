# General clause-quality and coordinated-edit fixes

## Usability and generation completion, 2026-10-13

Metadata remains 2.1. First-review candidates and a completeness gate now distinguish missing generation, incomplete semantic work, missing facts, coordinated edits and insufficient legal scope. The gate requests repair before normal delivery; Python does not generate legal language or fabricate a model receipt. Negotiation recommendations have explicit acceptance, and pre-reviewed fact fields can be filled locally under a bounded policy. Free substantive changes still require WorkBuddy review of the affected scope.

The editor uses one card-local proposal area, preserves drafts across filters and Escape, restores focus and selected candidates, preserves exact partial operations, maps unaffected evidence ranges and distinguishes actual file writing from a download request. Ordinary text around genuine DOCX tabs and line breaks can be edited while the XML controls remain intact. Formatting tab-stop declarations are no longer included as text. Controlled legacy migration refuses changed or affected plan ranges rather than guessing.

Professional knowledge extensions have separate versions, article completeness/digests, verification metadata and temporal scope. No real specialist statutes were added in this increment; uncertain historical applicability remains a review task. Core law snapshots and preferences remain intact.

Executed checks for this increment: 53 Python tests, 39 existing and 48 new real Edge browser checks, an eight-state synthetic contract matrix, and two additional final held-out cases. The same code was privately regressed against two user documents; those documents and private reports are excluded from this repository. Semantic receipts in fixtures are synthetic golden data for protocol/execution testing, not independent model or lawyer evaluations. Native WorkBuddy end-to-end execution and Word page rendering were not verified. Fact-field filling supports approved dates, bounded decimals and short text; it is not a general tax, price-mechanism or liability generator.

Use [the current usability workflow](references/usability_workflow.md) and [knowledge extension instructions](references/knowledge_extensions.md). Old standalone HTML must be re-rendered to get the new code. The following notes describe the preceding baseline increment.

Incremental changes keep metadata.version at 2.1. The fixed editor remains offline, and WorkBuddy remains responsible for semantic review. No server or browser DOCX export is required.

New contract-independent plan quality/execution modules require exact target text, confirmed business conditions, source revision baseline, relationship evidence, and a plan/scope-bound ten-item WorkBuddy semantic receipt. Missing conditions, unresolved relations, conflicting actions, stale receipts and unsupported legal scope block application. Formal clauses and explanatory text are separate. Multi-location plans are previewed, applied, confirmed, undone and restored as complete groups. Applied risks remain subject to re-review.

Python validates declared data and receipts; it does not perform legal reasoning, prove the completeness of the model's relationship graph, or authenticate the reviewer using a digital signature. New contract types do not require type-specific production rules. Additional document structures or legal domains require separately verified resources.

Executed tests: 16 general quality tests, 12 existing/Word-export regression tests, 7 native tracked-revision tests, 8 states across six synthetic contract types, 2 final held-out samples, and 39 real Edge browser checks. Browser-confirmed edits exported to test Word were re-extracted and matched independently replayed full text. Semantic receipts are explicit synthetic golden data, not independent model or lawyer evaluations. Word page rendering was not verified.

The final held-out inputs did not cause production code changes. One initial test omitted a required source quote; the validator correctly blocked it, and the fixture was completed without changing production rules. Real user documents and private reports are not included in this repository.
